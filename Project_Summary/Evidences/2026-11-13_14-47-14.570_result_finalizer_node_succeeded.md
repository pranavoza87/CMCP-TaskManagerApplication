#### ENH-13 — Functional
- **Title:** Fix delete flow to prevent stale UI when API returns 404
- **Key detail:** In the React UI, `handleDelete` calls `deleteTask(id)` then `load()`. If `deleteTask` throws on **404** (example response: `404 {"error":"task not found"}`) from `DELETE /api/tasks/:id` in **`backend/src/server.js`**, the `load()` call is skipped due to `catch`, leaving **stale task row visible**.
- **Referenced files/components:**
  - Backend route: **`backend/src/server.js`** (`DELETE /api/tasks/:id`)
  - Frontend behavior referencing `handleDelete`, `deleteTask`, `load()`
- **Acceptance criteria (high level):**
  - On **404** delete: show error and refresh list so stale row is removed
  - On **204** delete: refresh list and deleted task disappears
- **Priority:** 13

#### ENH-14 — Technical Debt
- **Title:** Add API health endpoint for basic operability checks
- **Key detail:** Backend currently only has routes:
  - `GET /api/tasks`
  - `POST /api/tasks`
  - `DELETE /api/tasks/:id`
  in **`backend/src/server.js`**, and **no health endpoint**.
- **Requested change:** Add **GET `/api/health`** (or similar) returning **HTTP 200** JSON, without modifying task data.
- **Acceptance criteria:** Returns 200 JSON; does not write/modify task data
- **Priority:** 14

#### ENH-15 — NFR (Non-Functional Requirement)
- **Title:** Add request/error logging to improve diagnosability
- **Key detail:** Observability is minimal—only startup log `console.log("API listening...")` in **`backend/src/server.js`**. No request/error logs.
- **Requested change:** Add lightweight request logging (method + path) and log unexpected errors server-side while keeping frontend error contract.
- **Referenced file:** **`frontend/src/api.js`** expects failures with JSON containing `{error}`.
- **Acceptance criteria:** Logs method/path for requests; logs unhandled errors; returns JSON errors consistent with `{error}` contract.
- **Priority:** 15

#### ENH-16 — Validation
- **Title:** Add server-side maximum title length validation and client-side maxLength
- **Key detail:** `POST /api/tasks` currently validates only non-empty trimmed string for `title` in **`backend/src/server.js`**. UI input has no `maxLength` in **`frontend/src/App.jsx`**.
- **Requested change:** Enforce a maximum title length in API; add same `maxLength` in UI input.
- **Acceptance criteria:** API returns **400** with JSON `{error}` when title too long; UI enforces max length via `maxLength`.
- **Priority:** 16

#### ENH-17 — Security/Auth
- **Title:** Make allowed CORS origins configurable and default to least privilege for non-dev
- **Key detail:** Backend uses open CORS with `app.use(cors())` in **`backend/src/server.js`**, flagged as a security concern if exposed publicly.
- **Requested change:** Introduce configuration for allowed origins:
  - Default remains **allow-all** to avoid breaking local development
  - When configured, restrict origins (no CORS headers for non-allowed origins)
- **Acceptance criteria:** Default behavior unchanged unless configured; allowlist enforced when set.
- **Priority:** 17
